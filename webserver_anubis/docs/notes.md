### Environment

Anubis is configured with environment variables, see the table linked above.
All variables are set with `anubis_environment`, which is merged over the defaults of the role.

The role requires the following variables and checks them before it changes anything:

| Variable | Default of the role | Description |
|---|---|---|
| `BIND` | `:8923` | Address Anubis listens on, use the port in the labels of a reverse proxy |
| `BIND_NETWORK` | `tcp` | Address family of `BIND` |
| `POLICY_FNAME` | `/data/cfg/botPolicies.yaml` | Path of the bot policy generated by the role inside the container |
| `TARGET` | – | URL of the protected service, has to be set |

```yaml
anubis_environment:
  TARGET: 'http://192.168.99.21:80'
  COOKIE_DYNAMIC_DOMAIN: 'true'
  SERVE_ROBOTS_TXT: 'true'
  WEBMASTER_EMAIL: 'webmaster@example.org'
```

### Secrets

Variables carrying secrets, e.g. `ED25519_PRIVATE_KEY_HEX`, are not set in `anubis_environment`, but as podman secrets with `anubis_secrets`.
Every secret is created with `podman secret create` and passed into the container as environment variable `target`:

```yaml
anubis_secrets:
  - name: 'anubis_ed25519_private_key'
    data: "{{ vault_anubis_ed25519_private_key }}"
    target: 'ED25519_PRIVATE_KEY_HEX'
```

A `target` must not be set in `anubis_environment` as well, the role checks this.

### Migration from the single variables

The former single variables were removed, set the environment variables in `anubis_environment` instead:

| Former variable | Environment variable |
|---|---|
| `anubis_port`, `anubis_bind` | `BIND` |
| `anubis_bind_network` | `BIND_NETWORK` |
| `anubis_cookie_dynamic_domain` | `COOKIE_DYNAMIC_DOMAIN` |
| `anubis_policy_fname` | `POLICY_FNAME` |
| `anubis_redirect_domains` | `REDIRECT_DOMAINS` (comma separated) |
| `anubis_serve_robots_txt` | `SERVE_ROBOTS_TXT` |
| `anubis_socket_mode` | `SOCKET_MODE` |
| `anubis_strip_base_prefix` | `STRIP_BASE_PREFIX` |
| `anubis_target` | `TARGET` |
| `anubis_xff_strip_private` | `XFF_STRIP_PRIVATE` |

The role does not set `COOKIE_DYNAMIC_DOMAIN`, `SERVE_ROBOTS_TXT`, `SOCKET_MODE`, `STRIP_BASE_PREFIX` and `XFF_STRIP_PRIVATE` anymore, Anubis uses the same defaults.

### Bot policy

The bot policy is written to `anubis_home/botPolicies.yaml` and mounted into the container.
`anubis_config` replaces the default policy completely.
The default policy allows the networks in the global variable `trusted_hosts` without challenge, so `trusted_hosts` has to be defined when the default policy is used:

```yaml
trusted_hosts:
  - '192.168.99.0/24'
  - 'fd00::99:0/112'
```

### Restarts

A running container is restarted when `botPolicies.yaml`, a secret or the quadlet unit changed, the first start of the container does not trigger an additional restart.

### Tests

The molecule scenario `default` runs the role in two [tart](https://tart.run) VMs on a macOS controller, the base VM has to be Debian 13.
The base VM is cloned for every platform and the clones are deleted afterwards, the base VM itself is never changed.
The playbooks creating and destroying the VMs are shared by all tart scenarios and live in `.molecule/tart/` in the repository root.

| Platform | Test case |
|---|---|
| `molecule-anubis-ipv4-only` | Container with IPv4 address only |
| `molecule-anubis-ipv6` | Container with IPv4 and IPv6 address, an additional variable in `anubis_environment` and a secret in `anubis_secrets` |

`prepare` sets up podman and the network `podman-molecule` with the role `container_podman` and pulls the image.
`verify` checks the quadlet unit including the secrets, the bot policy, the service, the podman secrets and the container addresses and environment.
The VMs need access to `ghcr.io` for the image.

Requirements on the controller: `tart`, `sshpass` (`brew install hudochenkov/sshpass/sshpass`), `molecule` and the collection `containers.podman`.

| Environment variable | Default | Description |
|---|---|---|
| `MOLECULE_TART_IMAGE` | `ghcr.io/cirruslabs/debian:latest` | Base VM or image that is cloned |
| `MOLECULE_TART_USER` | `admin` | SSH user of the base VM |
| `MOLECULE_TART_PASSWORD` | `admin` | Password of the SSH user, used to install the SSH key and for `sudo` |

```shell
cd webserver_anubis
MOLECULE_TART_IMAGE='debian' molecule test
```
