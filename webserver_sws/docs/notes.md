The role runs [Static Web Server](https://static-web-server.net/) with the image `ghcr.io/static-web-server/static-web-server` as podman quadlet.
`sws_home` contains the configuration file `sws.toml` and the content served by Static Web Server:

| Path | Mounted as | Description |
|---|---|---|
| `sws.toml` | `/sws.toml` | Configuration file, generated by the role |
| `public/` | `/public` | Content of the default host |
| `vhosts/<name>/` | `/var/vhosts/<name>` | Content of a virtual host |

The role creates the directories, the content has to be deployed separately.
The image is built from `scratch` and runs in `/`, Static Web Server reads `./sws.toml` and serves `./public` by default,
so the role sets neither `SERVER_CONFIG_FILE` nor `SERVER_ROOT`.

```yaml
- name: 'Configure www.example.org'
  become: true
  hosts: 'webserver'
  roles:
    - 'common_filters'
    - 'common_globals'
    - 'webserver_sws'
```

### Configuration

`sws_config` is the content of `sws.toml` with the sections `general` and `advanced`, the role has no defaults,
without `sws_config` Static Web Server uses its defaults (port 80 on all addresses):

```yaml
sws_config:
  general:
    port: 8080
    log-level: 'info'
    compression: true
    security-headers: true
  advanced:
    headers:
      - source: '**/*.html'
        headers:
          Cache-Control: 'no-cache'
    redirects:
      - source: '/old'
        destination: '/new'
        kind: 301
```

- The keys are the keys of the [configuration file](https://static-web-server.net/configuration/config-file/) in kebab case.
- TOML is typed: booleans are `true` and `false`, numbers are written without quotes.
- `null` removes a section or an option, the other values are written as they are.
- The values of `sws.toml` take precedence over the environment and the arguments of Static Web Server.
- `sws.toml` is written with the filter [`community.general.to_toml`](https://docs.ansible.com/ansible/latest/collections/community/general/to_toml_filter.html),
  it needs the Python library [tomlkit](https://pypi.org/project/tomlkit/) on the Ansible controller, e.g. `pip install tomlkit` in the environment of Ansible and molecule.

### Virtual hosts

Virtual hosts are entries of `advanced.virtual-hosts` with `host` and `root`, the root is a directory `/var/vhosts/<name>`:

```yaml
sws_config:
  advanced:
    virtual-hosts:
      - host: 'example.com'
        root: '/var/vhosts/example.com'
      - host: 'example.org'
        root: '/var/vhosts/example.org'
```

The role creates `<sws_home>/vhosts/<name>` for every root, Static Web Server stops if the root of a virtual host does not exist.
Requests with a `Host` header not listed in `advanced.virtual-hosts` are answered from `public/`.

### Secrets

Basic authentication (`basic-auth`, `user:bcrypt-hash`) is a secret and passed with `sws_secrets`:

```yaml
sws_secrets:
  - name: 'sws-basic-auth'
    data: "{{ vault_sws_basic_auth }}"   # htpasswd -nbB user password
    target: 'SERVER_BASIC_AUTH'
```

- Static Web Server reads no file for a secret (there is no `*_FILE` variable) and `sws.toml` cannot reference a file,
  so the secret is passed in the environment with `type=env,target=SERVER_BASIC_AUTH`. The quadlet unit contains only the name of the secret.
- The options of `sws.toml` take precedence over the environment, so `basic-auth` must not be set in `sws_config`, the role rejects it.
- Basic authentication protects all pages, also of the virtual hosts.
- A changed secret restarts the running service.

### Allowed variables

The lists of allowed options prevent unexpected behavior by accident, e.g. a misspelled option Static Web Server ignores with a warning only.

- `webserver_sws__config_allowed` lists the options of `general` and `advanced`, generated from `src/settings/file.rs` of Static Web Server v2.44.3
  with the default features of the image. `memory-cache` (experimental, not part of the image) and `windows-service` are not allowed.
- `webserver_sws__advanced_keys` lists the keys of the entries of `headers`, `rewrites`, `redirects` and `virtual-hosts`.
- `webserver_sws__secrets_allowed` lists `SERVER_BASIC_AUTH`.
- `webserver_sws__environment_allowed` is empty: the variables `SERVER_*` of the image are options of `sws.toml`, the image needs no other variables.

### Container

| Variable | Description |
|---|---|
| `sws_home` | Directory of the configuration and the content on the host |
| `sws_ip`, `sws_ipv6` | Addresses of the container in `sws_network` |
| `sws_hostname` | Hostname of the container |
| `sws_timezone` | Time zone of the container |
| `sws_labels` | Labels of the container, e.g. for Traefik |
| `sws_version` | Tag of the image, default `2` (the latest release 2.x) |
| `sws_container` | Merged into the container default, not recursive (e.g. `publish`, `volumes`, `requires`, `wants`, `after`) |
| `sws_autoupdate_enabled`, `sws_autoupdate_schedule` | Updates of the image by `container_update` |

TLS (`http2-tls-cert`, `http2-tls-key`) needs the files in the container, they are mounted with `volumes` in `sws_container`.
Usually TLS is terminated by the reverse proxy.

### Validation

Before any change the role checks:

- that `sws_secrets` is a list of entries with name, data and target and unique names,
- that `sws_config` is a dictionary of the sections `general` and `advanced` with known options, without `basic-auth`,
- the types of `general`: booleans, numbers with their ranges (`port` 1 to 65535, `grace-period` 0 to 255), the values of `log-level`,
  `compression-level` and `directory-listing-format`, the lists `trusted-proxies` and `directory-listing-download` (`targz`), strings without line breaks,
- that the options of `advanced` are lists of dictionaries with their mandatory and known keys, the kinds of the redirects 301 or 302,
  the virtual hosts with unique host names and roots `/var/vhosts/<name>`,
- that the container has no environment variables and only the secret `SERVER_BASIC_AUTH`.

After the start the role waits until Static Web Server listens on its port, otherwise it fails with the journal of the service.

### Restart and updates

- A changed configuration, secret or quadlet unit restarts the running service, the first start does not trigger an additional restart.
- Changed content needs no restart, Static Web Server reads the files on every request.
- Updates of the image are done by `container_update` with `sws_autoupdate_enabled` and `sws_autoupdate_schedule`.

### Migration

- `sws_vhosts` is `advanced.virtual-hosts` of `sws_config`, every host `<host>` is `{ host: '<host>', root: '/var/vhosts/<host>' }`.
- The configuration is mounted to `/sws.toml` instead of `/etc/sws.toml` and the content to `/public` instead of `/var/public`,
  `SERVER_CONFIG_FILE` and `SERVER_ROOT` are removed. Pages referring to `/var/public` (e.g. `page404`) have to use `/public`.
- `/etc/localtime` and `/etc/timezone` of the host are not mounted anymore, podman sets the time zone.
- `sws_version` is new, the tag `2` was fixed before.
- The quadlet unit gets the dependencies of `sws_container` (`requires`, `wants`, `after`, `part_of`, `binds_to`, `requires_mounts_for`).
- `podman___update_mode` is removed, see Restart and updates. `sws_autoupdate_schedule` is new.
- The tags are `webserver` and `webserver_sws`.

### Tests

The molecule scenario `default` runs the role in [tart](https://tart.run) VMs on a macOS controller, created by `.molecule/tart/create.yml`.

| Platform | Tested |
|---|---|
| `molecule-sws-default` | only the mandatory variables, the defaults of Static Web Server |
| `molecule-sws` | IPv6, `port`, `log-level`, `compression`, `security-headers`, `null`, `headers`, `redirects`, two virtual hosts, basic authentication as secret, labels, `wants` and `after` of the quadlet unit |

`prepare` installs `tomlkit` into the Python of Ansible on the controller if it is missing (see Configuration).

`prepare` stops the timers of apt and waits for running updates (a new clone catches up on them and holds the dpkg lock),
installs podman and the network, pulls the image and creates test pages in `public/` and `vhosts/`.

`side_effect` runs the role with invalid values (expect ERROR) and checks the message and that the configuration and the quadlet unit are unchanged.
On `molecule-sws` it changes `log-level`, Static Web Server restarts, on `molecule-sws-default` a run without a change neither changes nor restarts anything.

`verify` checks the quadlet unit (image, addresses, mounts, the secret without the hash, no environment, no files of the time zone),
`sws.toml` (owner, mode, options), the service with its journal (no unused keys) and without automatic restarts, the addresses and the time zone of the container,
requests the pages via IPv4 and IPv6 and the virtual hosts with their `Host` header, and on `molecule-sws` basic authentication (401 without and with a wrong password),
the header of `advanced.headers` and the redirect.

```shell
cd webserver_sws && MOLECULE_TART_IMAGE='debian' molecule test; cd ..
```
